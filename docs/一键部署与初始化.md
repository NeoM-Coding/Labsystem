# 一键部署与初始化

## 功能范围

[`scripts/deploy.sh`](../scripts/deploy.sh) 负责启动 `compose.yml` 中的基础设施，并执行以下初始化：

1. 等待 MySQL 和 Permify 就绪。
2. 幂等执行 `sql/schema.sql`。
3. 向 MySQL 创建或更新默认超级管理员。
4. 上传 `auth/schema/lab-system-v2.perm`。
5. 写入 `app:global#super_admin@user:{userId}` Permify relation。

当前脚本部署的是项目 Docker 基础设施。Java 服务仍以 Maven/IDE 进程运行，因为仓库尚未为 `web`、`base`、`mqtt` 和 `rule-engine` 定义应用镜像。

## 使用方法

首次运行会自动从 `.env.example` 创建 `.env`：

```bash
./scripts/deploy.sh
```

建议先手动创建并修改配置：

```bash
cp .env.example .env
./scripts/deploy.sh deploy
```

其他命令：

```bash
./scripts/deploy.sh bootstrap
./scripts/deploy.sh status
./scripts/deploy.sh logs
./scripts/deploy.sh down
```

脚本不会在 `down` 时删除 volume。需要清空数据时应明确执行 Docker Compose 的 volume 删除操作。

## 默认管理员密码

部署脚本不会在部署机运行 Java，也不会把明文密码直接写入 MySQL。`.env` 中同时保存登录说明和由 Java Test 预编译的 BCrypt 摘要：

```dotenv
SUPER_ADMIN_PASSWORD='Admin@123456'
SUPER_ADMIN_PASSWORD_BCRYPT='$2a$...'
```

修改密码时，先运行测试生成摘要：

```bash
source ~/.zshrc
./mvnw -pl base -am \
  -Dtest=SuperAdminFixtureTests \
  -Dsuper.admin.password='新的密码' \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

将测试输出的 `SUPER_ADMIN_PASSWORD_BCRYPT` 写入 `.env`，并同步修改 `SUPER_ADMIN_PASSWORD`。正常测试会验证 `.env.example` 中两者一致。

## 幂等边界

- MySQL schema 使用 `CREATE TABLE IF NOT EXISTS`。
- 超级管理员按 username 查找；重复部署会刷新密码摘要、邮箱、备注和软删除状态。
- 若配置的用户 ID 或显示名称已被其他用户占用，脚本会失败而不是覆盖该用户。
- Permify schema 每次 bootstrap 都会上传一个新版本，因为内存模式重启后 schema 会丢失。
- Super Admin relation 写入前会先读取，已存在时跳过。

Permify 官方当前持久化数据库支持 PostgreSQL，不支持直接复用本项目 MySQL。现阶段 Compose 保持 Permify 内存模式，通过部署脚本完成自动恢复；需要让 Permify 数据跨容器重启持久化时，应单独引入 PostgreSQL。
