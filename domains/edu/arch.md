# 教务域核心设计

本文描述 `domains/edu` 当前实现的设计边界、数据模型和关键流程。内容以现有源码、测试与 `sql/schema.sql` 为准，用于维护学期和实验室课表相关能力。

## 1. 模块定位

教务域负责两类核心数据：

- **学期**：维护学期名称及起止日期，为课表提供时间基准。
- **课表**：维护某学期、某实验室内的课程安排，并阻止实验室或教师发生时间冲突。

教务域对外通过 Dubbo 暴露 `SemesterService` 和 `TimetableService`。`api` 子模块只承载可序列化的 RPC 契约，`service` 子模块负责业务规则、授权接入、审计接入、事务及持久化。

### 负责的事情

- 学期的查询、创建、修改和删除。
- 课表的查询、创建、修改、删除及按“学期 + 实验室”清空。
- 课表字段校验、单/双周语义和排课冲突判断。
- `.xlsx` / `.xls` 课表解析与逐条导入。
- 将学期快照冗余到课表，并在修改学期时同步刷新。
- 按当前用户可见实验室收敛课表读取与写入范围。
- 为操作接入统一授权、审计及链路追踪。

### 不负责的事情

- 不维护实验室、用户、角色或权限关系，只消费会话中已经计算好的用户与实验室范围。
- 不负责 HTTP 会话、文件上传协议和响应包装；这些由 Web 层完成，再转换成教务 RPC 命令。
- 不生成通用校历，不处理调课、停课、补课、节假日或教室容量等高级排课规则。
- 不验证教师是否来自人员主数据；教师目前以规范化后的名称参与冲突判断。
- 不把课表自动下发到下位机，也不拥有设备控制逻辑。
- 不负责 BI 报表查询。数据库视图只提供从周期课表展开为课程实例的稳定数据接口。

## 3. 领域模型

### 3.1 学期 Semester

学期包含：`id`、`name`、`startDate`、`endDate` 及通用创建、更新、软删除时间。

业务不变量：

- 名称必须完整匹配 `YYYY-YYYY 第N学期`。
- `startDate < endDate`。
- 名称全局唯一；应用层预检查和数据库唯一索引共同兜底。
- 存在课表记录的学期不能删除，必须先清理课表。

学期是课表并发写入的锁定对象。新增、修改、删除或清理某学期课表时，服务通过 `SELECT ... FOR UPDATE` 锁住对应学期行，使同一学期内的“检查冲突 + 写入”串行化。

### 3.2 课表 Timetable

一条课表表达一个周期性课程规则，而不是某一天的单次课程：

| 字段 | 含义 |
| --- | --- |
| `semesterId` | 所属学期 ID |
| `semesterInfo` | 学期 JSON 快照 |
| `laboratoryId` | 上课实验室 ID |
| `courseName` / `teacherName` | 课程、教师名称 |
| `weekType` | `Single` 单周、`Double` 双周、`Both` 每周 |
| `startWeek` / `endWeek` | 闭区间周次，最小为 1 |
| `startSection` / `endSection` | 展示节次闭区间，当前为 1～11 |
| `startTime` / `endTime` | 实际占用时间 `[startTime, endTime)` |
| `weekday` | 1～7，分别表示周一到周日 |

节次和时间同时持久化，但用途不同：节次用于稳定呈现教学节次，时间用于精确冲突判断。创建和修改时两者都由调用者提交并分别校验；导入时可以由节次推导时间，也可以由时间映射到所覆盖的节次。

`semesterInfo` 是读模型快照，避免查询课表时再逐条读取学期。修改学期时，主记录和所有课表快照在同一数据库事务内更新。`semesterId` 仍是归属和查询依据；数据库刻意不建立跨表外键，删除约束由服务实现。

## 4. 排课冲突规则

创建和修改课表时，服务先锁定学期行，再读取该学期同一星期的候选记录。两条课表只有同时满足以下条件才冲突：

1. 实验室相同，**或**教师名称相同。教师名比较会去除首尾空白并忽略大小写。
2. `weekday` 相同。
3. 周次闭区间存在交集。
4. 周类型在交集内至少存在一个共同生效周：
   - 任一方为 `Both` 时相交；
   - `Single` 与 `Double` 不相交；
   - 两者同为单周或双周时，交集内必须实际包含对应奇偶性的周。
5. 时间半开区间重叠，即 `a.start < b.end && b.start < a.end`。

因此，`09:40` 结束和 `09:40` 开始的两节课可相邻安排；同一教师在不同实验室的重叠课程仍会冲突；仅节次编号重叠而实际时间不重叠不会触发冲突。

更新课表时会排除自身 ID 后重新检查。冲突响应为 `409`，并携带首条冲突课表 ID。

当前冲突检查依赖应用层锁和查询，不是数据库唯一约束。所有新增或修改入口必须先锁定所属学期，不能绕过 `createLocked` / `requireNoConflict` 直接写表，否则会破坏并发一致性。

## 5. 核心流程

### 5.1 查询

学期查询支持名称模糊匹配，按开始日期、创建时间倒序返回。

课表查询要求学期存在。请求实验室为空时使用当前会话可见实验室全集；不为空时取“请求 ID 与可见 ID”的交集，越权 ID 不会扩大查询范围。结果按实验室、星期、开始节次、开始时间排序，实验室名称来自当前用户上下文，学期信息来自课表快照。

### 5.2 学期写入

- **创建**：校验格式和日期 → 检查重名 → 写入；数据库唯一索引捕获并发重名。
- **修改**：锁学期 → 校验并检查重名 → 更新主记录 → 同事务刷新所有关联课表的 `semesterInfo` 与更新时间。
- **删除**：锁学期 → 统计课表 → 有课表则返回 `409`，否则软删除学期。

### 5.3 课表写入

- **创建**：检查实验室可见性 → 校验字段 → 锁学期 → 写入学期快照 → 检查冲突 → 保存。
- **修改**：读取原记录 → 同时检查原、新实验室可见性 → 构造完整替代记录 → 锁新学期 → 保留 ID 和创建时间 → 检查冲突 → 更新。
- **删除**：读取记录并检查其实验室可见性 → 锁所属学期 → 删除。
- **清空**：检查目标实验室可见性 → 锁学期 → 删除该学期、该实验室下的课表。

写操作使用 Spring 事务。课表更新允许变更学期和实验室；调用者必须提交完整字段，而不是局部补丁。

## 6. Excel 导入

Web 层将 multipart 文件读取成可序列化的 `TimetableImport`，RPC 服务再次校验：

- 文件名后缀只能是 `.xlsx` 或 `.xls`。
- 内容不能为空且默认不超过 5 MiB，可由 `EDU_IMPORT_MAX_BYTES` 调整。
- 文件魔数必须符合 ZIP/XLS 复合文档格式，随后由 Fesod Sheet 解析。
- 目标实验室必须在当前用户可见范围内。

工作表不使用表头，所有行都会被读取；第 0 列代表周一，第 6 列代表周日。一个单元格可用英文逗号分隔多门课，每项格式为：

```text
课程名称<>时间信息<>教师名称
```

时间信息支持：

```text
1-16周[1-2节]
1-8周(单)[10:00-10:45]
2-16周(双)[18:40-20:15]
```

解析会去除换行并将中文冒号替换为英文冒号。旧的四段式格式（例如额外携带教室）不会兼容，而是作为行、列明确的错误返回。

导入分两个阶段：

1. 解析整个工作簿，收集合法条目和格式错误。
2. 按行、列顺序逐条开启独立事务，复用正常创建路径的学期锁、快照与冲突校验。

因此导入是**部分成功**语义，不是整份文件原子提交。某条失败只回滚该条，后续条目继续处理；返回 `ok`、`fail` 以及按行列排序的错误列表。审计层把一次导入请求记录为一个聚合操作，而不是为每个单元格生成审计事件。

## 7. 授权、审计与跨模块边界

### 授权契约

所有 RPC 方法都经过 `@ActionAuthorized`：

- 学期查询：`list_semester`
- 学期写操作：`manage_semester`
- 课表查询：`view_timetable`
- 课表写操作与导入：`manage_timetable`

以上是全局应用级动作授权。除此之外，课表服务还要求有效用户上下文，并以其中的实验室可见范围做数据级约束。教务域不查询或解释权限关系，也不自行扩张实验室范围。

### 审计契约

学期和课表写命令实现 `Loggable`，写方法以 `@Audited` 发布统一操作描述。审计对象类型为 `semester` 或 `timetable`；清空和导入使用 `semesterId:laboratoryId` 标识聚合范围。教务域仅声明审计事实，不管理审计日志的存储与查询。

### Web 契约

Web 层暴露 `/api/edu/semesters` 与 `/api/edu/timetables`，负责 HTTP 参数、multipart 和 RPC 响应转换。更新接口始终以路径 ID 覆盖请求体 ID，避免客户端用 body 改写目标资源标识。业务不变量仍在教务服务校验，不能只依赖控制器。

### 基础数据契约

`laboratoryId` 是外部实验室标识。教务库不保存实验室详情和外键；展示名称只来自用户上下文的实验室范围快照。这使教务域无需同步完整实验室模型，但也意味着上下文缺少名称时返回值中的 `laboratoryName` 可以为空。

## 8. 持久化与一致性

`semester` 与 `timetable` 使用 MyBatis-Plus，继承统一实体的 ID、创建、更新和软删除字段。数据库提供字段级检查约束、学期名称唯一索引，以及面向课表查询和冲突候选扫描的组合索引。

一致性策略分三层：

- **输入校验**：服务在写入前给出明确的 `400/404/409` 业务错误。
- **并发串行化**：以学期行为锁粒度，保护同一学期的冲突检查、课表写入以及学期快照刷新。
- **数据库兜底**：唯一索引、日期、周次、节次、时间、星期及枚举检查约束防止非法数据落库。

跨学期写入可以并行；同一学期写入会串行。Excel 每条记录独立获得锁并提交，这优先保证错误隔离，而不是批量吞吐和全文件原子性。

数据库还提供 `bi_edu_course_occurrence`：借助 1～60 周维度表，把周期课表按学期开始日所在周展开为实际日期和起止时间，并按单/双周及学期日期边界过滤。它是分析侧只读契约，不参与在线排课和冲突判断。

## 9. 扩展原则

- 新增排课写入口时必须复用学期锁、领域校验和冲突检查，禁止直接调用 Mapper 保存。
- 新增周类型时，需要同步修改 `WeekType`、冲突计算、数据库检查约束和 BI 展开条件。
- 调整节次表时，需要同步修改 `SECTIONS`、数据库节次约束、历史数据迁移与导入测试。
- 引入教师 ID 后，应明确名称展示和唯一身份的分工，并迁移冲突判断，避免继续以名称作为身份。
- 若需要全文件原子导入，应新增独立模式或接口，不能悄然改变现有部分成功契约。
- 若增加调课、例外日期或节假日，应建模为独立规则或课程实例覆盖，不应继续堆叠在周期课表字段中。
- 若写入规模使学期级锁成为瓶颈，可细化锁粒度，但必须同时解决“同教师跨实验室冲突”的全局并发问题。
